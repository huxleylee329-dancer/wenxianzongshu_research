一次有限实验：从已验证的 SFT v1 开始，不做参数搜索

适用设备：单卡 NVIDIA GeForce RTX 4090。不要上传 API key 或 .env。
压缩包包含 v1 LoRA，不包含约 16GB 的 Qwen3-8B 基座模型。
启动脚本优先复用已有且 SHA-256 一致的基座；没有时下载并核验。
安装依赖和下载需要联网，但训练、评分不调用真实论文工具或外部模型 API。

上传 tool-calling-grpo-once-v1.zip 到 /home/featurize 后执行：

cd /home/featurize
test ! -e tool-grpo-once-v1 && python -m zipfile -e tool-calling-grpo-once-v1.zip tool-grpo-once-v1 && cd tool-grpo-once-v1 && bash run_grpo_once.sh --execute

不加 --execute 只做 CPU 预检，不下载、不加载 GPU、不训练。
已存在 runs/once 时拒绝重新执行；任何失败都不自动重试或恢复。

固定流程
1. 核验 12 个基座文件、固定依赖版本、v1 适配器。
2. policy 和 reference 都加载同一个 v1 适配器；只有 policy 可训练。
3. 10 个贪心 canary 必须逐字复现 v1 原输出，否则停止。
4. 固定 32 个训练池 prompt，各采样 4 个回答。
   至少 8 组同时含正确回答和较低奖励回答，且无截断，才继续。
5. 唯一一轮 GRPO：50 个提前选定的独立 prompt group，最多 50 步。
   使用 30 条原训练题和 20 条新增成对题；不是遍历全部 1200 条。
   每组 4 个回答；连续 32 组没有正确/较低奖励混合则提前停止。
   lr=5e-6，beta=0.02，temperature=0.7，top_p=0.9，top_k=50。
   dr_grpo，constant LR，无 warmup，num_iterations=1，seed=20261003。
6. 200 条开发集：总分 >180，DOI >=20，年份 >=13，歧义澄清 >12，
   越权错误 <=3，格式/合同错误 <=4；任何一项未满足都保留 v1。
7. 仅通过上项后才读取盲测题，v1 和候选各测同一 200 条一次。
   候选正确数不低于 v1，越权和格式错误不增加，才标记 candidate_accepted。
   不依据盲测结果继续调参或重训。

预算与停止
从 GPU worker 启动计时，上限 60 分钟，包含加载、信号探测、训练和评估。
超时发出终止信号，最多再等 20 秒后强制停止并打包；安装/下载不计入该时限。
这不是云实例的计费上限。脚本退出不会自动归还实例，也不会停止租赁计费。
实际时长和新配置显存尚未在云端测量；不能保证训练有收益。

结果
下载 runs/grpo-once-results.zip，然后在平台归还实例。
压缩包包含安全进度、评分、输出以及候选或最后完整保存的适配器（如有）。
每 10 步保存一次，不把未通过验收的 checkpoint 当成可部署模型。
不保存大基座，不复制所有重复 checkpoint 到下载包。
超时/失败/无学习信号/验证未通过都保留本地已验证的 v1。
candidate_accepted 也只代表这个离线合成工具选择任务通过验收，不代表整个学术工作流已验证。

数据说明
保留原始 1000 条训练数据，新增 100 对/200 条单条件对照题，共 1200 条。
新增标签用确定性的离线工具环境校验；尚未做逐条人工审核。
开发集用于诊断并影响了新数据设计，不宣称它是独立最终泛化测试。
训练 prompt 不包含 reference、goal_ids 或私有 world。
验证/盲测的 oracle 留在评分侧，不进入模型输入或训练数据集。

本地只做 CPU 单元测试、哈希、语法和打包校验，未运行真实 GPU 训练。
